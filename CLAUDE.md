# Handkerquest — notes for Claude

WoW addon: Objective Tracker sorting/filters + (?)/(•••) quest stacks, and the "Field Tally" parchment
(a pile of handwritten pages listing quest items to gather and tasks to do). Single file: `HandkerSheaf.lua` (was `Handkerquest.lua`, then `Handkerchief.lua` after v2.3.0, renamed again after v2.4.1; the in-game title is "HandkerSheaf"; the folder, `.toc`, addon name and
SavedVariables stay "Handkerquest" so players' installs and settings carry over).
Version lives only in `Handkerquest.toc` (`## Version`): the options heading reads it live (`CFQ.AddonVersion`,
`C_AddOns.GetAddOnMetadata`; no number in the code to bump). Release commits are titled `vX.Y.Z`.
Formerly "Cache ForQuest" (renamed in v1.3.0: handkerchief + quest, after Bilbo setting off without his handkerchief).
Internal names keep the old `CFQ` / `QRF_` prefixes on purpose — renaming `QRF_SavedState` would wipe
players' settings. Slash: `/hanky`, `/handkerquest`, legacy `/cfq`.

## Client
- Flavor "wowf" (WoW Forever), `## Interface: 16001`, but a **retail-style UI**: `QuestObjectiveTracker`
  module with `.ContentsFrame`, `C_QuestLog`, `C_SuperTrack`, `Settings` canvas panels.
- Client fonts are `.slug` files — don't ship custom TTFs without testing. The tally uses built-in
  `Fonts\MORPHEUS.TTF` (Quill script), `SKURRI.TTF` (Rough scrawl, Blotted scrawl) or the standard font
  (Plain print), user-selectable in `P.FONT_STYLES`.
- Most of the UI is drawn in code (`SetColorTexture`, gradients, `CreateLine`, Blizzard textures). The only
  art files are the texture looks in `textures/`, all procedural (no stock or Blizzard art), generated by
  `tools/TexGen.cs`. 32-bit uncompressed TGA, alpha = the shape, 512×512 unless noted. Regenerate from PowerShell:
  `Add-Type -Path tools\TexGen.cs -ReferencedAssemblies System.Drawing`, then
  - `[TexGen]::Rag(...)` → torn_rag, `::Crumpled(...)` → crumpled_paper
  - `::Stone(tga, png, 512, 5)` → stone, `::Bark(tga, png, 512, 3)` → bark, `::Leaf(tga, png, 512, 9)` → pipeweed_leaf
  - `::Leather(tga, png, 512, 4)` → etched_leather
  - `::ArcaneHaze(tga, png, 256, 2)` → arcane_haze (256), `::ArcaneRing(tga, png, 512, 7)` → arcane_ring
    (white lines; tinted and added in game)
  - `::ChalkGrain(tga, png, 128, 21, 0.165, 0.175, 0.195)` → chalk_grain (128, tiles)
  - `::InkBlots(tga, png, 256, 11)` → ink_blots (256, 2x2 atlas of white blots; tinted with the ink in game)
  - `::Marble(tga, png, 512, 5)` → sanctified_marble, `::GoldPlate(tga, png, 512, 6)` → gilded_plate,
    `::Vellum(tga, png, 512, 7)` → illuminated_vellum (insets set by hand inside the groove / rim / red rule,
    not the raw SafeRect: the writing must stay off the borders)
  - `::Icon(tga, png, 64, 3)` → icon (64, the AddOns-list icon, `.toc` `IconTexture`: a rag scrap with soot
    writing and a brown quill; drawn at 4x and averaged down so it reads at 16-20px)

  Re-measure `inset` / `imageCorner` with `[TexGen]::SafeRect(tga)` after regenerating.
  `media/` (CurseForge GIFs) and `tools/` are excluded from the package in `.pkgmeta`.

## Testing
- `"C:\Program Files (x86)\Lua\5.1\lua.exe" smoke.lua HandkerSheaf.lua` (Lua 5.1 = WoW's version).
  Must end with `N passed, 0 failed`. Syntax only: `luac.exe -p HandkerSheaf.lua`.
- `wowmock.lua` is loose (unknown capitalized methods are no-ops): catches logic errors and crashes,
  not visuals. Add `check(...)` lines to `smoke.lua` for every feature/fix; stub missing APIs in the mock.
- The user tests in game; say plainly what was and wasn't verified there.

## Design rules (each was a bug fix or a user decision — don't undo)
- **Stacking is visual only.** A deck holds only quests that already have a native tracker block;
  toggling stacks never adds/removes quest watches. Toggles call `CFQ.RequestNativeTrackerUpdate()`
  so Blizzard re-shows its blocks. `/hanky debug` dumps the tracker for in-game diagnosis.
  **Quest items on decks** (user decision; the eye / phial buttons used to vanish with the hidden block): a
  quest with a usable item still stacks, and its item gets **our own secure button left of the deck**
  (`CFQ.PlaceDeckItemButtons`, pool `CFQ.itemButtons`, `SecureActionButtonTemplate` type "item"): a row beside
  the collapsed deck, gliding next to its own card as the deck fans out. Parented to UIParent and placed by
  screen position, **never anchored to a deck** (that would make the deck protected and break its hover
  animation). Secure frames only move out of combat: in combat they stay put (`itemButtonsDirty`) and catch
  up on `PLAYER_REGEN_ENABLED`. `CFQ.QuestItemInfo` (`GetQuestLogSpecialItemInfo`; a finished quest only if
  `showItemWhenComplete`) → `qData.questItem` / `hasQuestItem`. If the client can't make secure buttons
  (`CFQ.ItemButtonsSupported`), such quests stay out of decks instead. Cache ReQuest (retail) does the same.
- **Field Tally lines** (user decision, v2.2):
  - **Items** = item objectives (`obj.type == "item"`; wording fallback when untyped) → `qData.itemObjectives`.
  - **Tasks** = enemies to slay and every other step, **one-step quests included** ("Sit by the fire";
    `CFQ.ExtractTaskObjectives` → `qData.taskObjectives`; `kind` = `slay` / `task`, both shown as "Tasks").
    A task of one (`single = true`) is just a box: no "0/1". (v2.2 left one-step quests off; reversed by the
    user because a new character whose only quest was one step never got a tally.)
  - Droppers, loot scans, hunt spots and minimap pins stay items-only. A slay line burns while your target is
    one of them (`CFQ.TargetIsToSlay`).
- **Keep the tally's controls simple** (user decision, v2.2): three inked 16px toggles left of the gear, nothing
  else. Items (a basket) and tasks (a sword) = `parchmentOpts.tallyLoot` / `tallyTasks` (one always stays on,
  `P.SetTallyShows`); tasks apart (lines) = `tallySeparate` (items first, then tasks under "Items" / "Tasks"
  headings, `P.DrawKindHeading`). Full ink = on, faded = off (`P.DrawQuickButton`, glyphs in `P.QUICK_GLYPHS`).
  **No other line orders** (A-Z, closest to done, presets and a mix menu were tried and removed): lines keep
  the tracker's quest order. Switching items or tasks off never puts the tally away
  (`P.ShouldHideUnfiltered`), even with "hide when nothing is nearby". Same three choices in the options panel.
- Rows: hand-inked box, quill tick, strike-through only over "count  name" (one strike per wrapped
  line); "(turn in)" is a separate unstruck note.
- **Page 1 is always "Near me"** (items within the Near me distance of the player, or progressed in the
  last 3 min). Pages 2+ are area pages grouped by `CFQ.pageGrouping`: `AREA` (explored subzone via
  `C_MapExplorationInfo`), `ZONE`, or `RADIUS` (leader clustering, optionally linked to the ••• slider).
  Pages with the same name always merge — never "Name II". In the options `RADIUS` is called **"Clusters"**
  and its slider "Cluster size" (user decision: "Distance" read as a distance, not a place).
  Quest positions: waypoint, then `CFQ.QuestPosNearPlayer` (`C_QuestLog.GetQuestsOnMap` on your map and its
  parents, so a new character needn't open the world map), then the world-map pin cache. A position on another
  map (Elwynn vs Northshire) is translated onto yours (`P.TranslatePos`). With none, a tracked quest whose log
  heading names your zone **or sub-zone** counts as near.
- "...only when something is nearby" (`hideWhenNothingNearby`) sits indented right under "Show the parchment
  tally list" (user decision). Switching the tally on while it stays hidden prints why (`P.TurnTallyOn`,
  `P.HiddenReason`). The options panel is a scroll frame (it's taller than the Settings window).
- Dog-eared bottom-right corner turns pages; resize grip is bottom-left. No ribbons, no Area/Zone/All cycle.
  On texture looks the fold is the material itself (`P.DrawMaterialFold`): the fold square reaches the
  **image's** corner, so the flap is the material's real edge (curved, lobed, torn) mirrored across the fold
  (8-value `SetTexCoord`) and the uncovered part follows that edge too; the crease is a dark strip of the
  material itself. No straight drawn edges/lines there (they'd overhang a curved edge). Rows are made lazily.
  `style.foldAtEdge` (leaf) keeps the square on the material's corner: its long edge runs along the fold.
  `P.PlaceCorner` puts it on the image's real corner (`style.imageCorner`, fractions measured from the TGA),
  re-placed on resize.
- No brass tack / yellow square at the top of the pile (removed at the user's request in v1.4).
- **Clicking a tally item = clicking the quest's icon in the Objective Tracker** (user decision, v1.4):
  `CFQ.ToggleSuperTrack` super-tracks the quest (click again to stop), adds no watches, opens nothing.
  Blizzard then shades the quest area on the map itself. Right-click = quest log. The addon draws
  **nothing on the world map** (an earlier ring/blob overlay covered Blizzard's highlights and was removed).
  The pin filter never dims or badges quest-area highlight pins (pins with `DrawBlob`).
- Hunting grounds = spots where the item ticked up (`CFQ.huntSpots`, saved) + the quest's map POI.
  Glow = in hunting grounds; fire = target drops it ("sure"), smoulder = name-only guess.
- **Droppers are evidence-first** (`CFQ.FindTargetDrops`): sure = the loot window showed the item from that
  npc (`CFQ.ScanLootWindow`, `GetLootSourceInfo` per slot) or the unit tooltip names the item/quest.
  Name guess only if not ruled out: ≥`P.RULE_OUT_LOOTS` tries without it, `UnitIsRelatedToActiveQuest`
  false, or tooltips list quests on this client but not this one. No bundled drop database.
- Hovering a tally item: tooltip goes beside the tally on the roomier side (`P.PlaceTooltip`); a small
  map preview (`CFQ.ShowMapPreview`: zone tiles, quest-area blob, rings, player dot) takes the candidate
  spot that is on screen and overlaps least (tally/tooltip weighted heavily, then `P.AVOID_FRAMES`).
  Blizzard's blob is only ever drawn *inside the preview*.
- Minimap: amber pins for the super-tracked quest's looted spots (`CFQ.UpdateMinimapPins`), on the rim
  when out of range; world coords: X = north, Y = west.
- Parchment look has no shaded header band (removed: it grew with the window). Grain is cropped from
  plain parchment below the quest-frame header art.
- Looks (`CFQ.parchmentStyle`, `P.STYLES`, in Look-list order). All tally colours come from the style
  table: don't hard-code ink colours. Picked from a **drop-down list** in the options (user decision: not a
  cycling button): `lookBtn.list` / `CFQ.lookDropDown`, one row per look with a swatch (the material's middle
  for texture looks, the paper colour for drawn ones), the current one ticked, a blurb on hover
  (`LOOK_BLURBS` in `CFQ.BuildOptionsPanel`: add one for every new look). A click outside closes it
  (a full-screen catcher on `DIALOG`). **The list's strata is re-set to `FULLSCREEN_DIALOG` every time it
  opens** (bug fix): Settings re-parents our panel when it shows it, which drops the list to the window's
  strata, under the catcher, and clicks on a look only closed the list. The catcher also picks the look
  under the mouse if a click still reaches it.
  `/hanky look <name>` and `P.CycleStyle` still step through the same order.
  - `HANDKERCHIEF`, `PARCHMENT` (drawn in code).
  - `CRUMPLED`: crumpled-and-flattened paper, pencil.
  - `RAG` (**default**, user decision): a strip torn off a dwarf's shirt: cream cotton weave, irregular torn
    edges with loose threads, the shirt's folded hem along the bottom with **no stitch/dotted line** (removed
    at the user's request), soot ink.
  - `STONE`: smooth dark river slate, chalk.
  - `BARK`: jagged chocolate-brown bark slab, letters carved into the reddish underbark.
  - `LEAF`: cured pipe-weed leaf (a nod to Longbottom Leaf): gold-brown, veins, **near-black** ink (brown ink
    vanished into the curing spots, user feedback); bends, so it keeps
    the textured fold. Its back pages **fan out from the stem** (`style.fan`) instead of lying flipped.
  - `LEATHER` ("Etched leather"): a rough-cut piece of supple tan garment leather, hide-shaped (leg lobes,
    knife-cut edges, a nick or two), soft drape folds, fine grain; no tooling or stitching (user decision).
    Letters pressed in (dark ink, pale lip below-right via `inkShadow`); real fold.
  - Paladin looks (user request: "something like the stone tablets"):
    - `MARBLE` ("Sanctified marble"): white marble tablet with an arched top and a gold-inlaid groove; letters
      cut and gilded (gold ink, dark `inkShadow` up-left), a soft gold holy light that breathes (`halo.color` +
      `pulse`, `P.PulseHalo`, no arcane circle). Rigid. Pages underneath only mirrored (`style.flips = { 1, 0, 1 }`)
      so the arches stay on top.
    - `GILDED` ("Gilded plate"): beaten gold, hammer dents, rolled rim, corner rivets; engraved dark letters with
      a bright lower wall (`inkShadow`). A band of light sweeps across now and then (`style.sheen`,
      `P.LayoutSheen` / `P.AnimateSheen`), kept inside `style.inset` so it never spills over the rim. Rigid.
    - `VELLUM` ("Illuminated vellum"): a holy book's page, gold-leaf border between a blue and a red rule, gold
      bosses with red quatrefoils in the corners; black iron-gall ink, red heading (rubric) whose **first letter
      is gilded** (`style.initial`), "(turn in)" in the border's blue. Bends: real fold.
  - `ARCANE`: a mage's writing hanging in the air: violet haze, a rune circle (`style.arcane`, added light,
    turning slowly on the top sheet), rising motes, a pulsing violet glow round the words, glowing corner
    mark, no pile (`P.LayoutArcane` / `P.AnimateArcane`). The circle is our own triangle-and-random-runes
    design, not WoW art, and deliberately has no six-pointed star.
    **Rune colour** (user decision): swatches **beside the Look button, shown only while Arcane script is the
    look** (`CFQ.runeColorRow`, `P.ARCANE_RUNE_COLORS`, saved `CFQ.arcaneRuneColor`). Runes drive the circle,
    motes, glow round the words, bleed, wash, corner mark.
  - `NATIVE`: see-through window, no pile. Uses the chosen handwriting (user decision: no lock to plain print).

  Texture looks set `style.image`: the sheet is one textured quad, the shadow is the same image tinted black
  and the pile is the image flipped per page (except the leaf's fan; `style.flips` overrides the flips).
- **Writing colour** (user decision: **every look, never conditional**): its own row under Handwriting
  (`CFQ.inkColorRow`, `P.INK_COLORS`; first swatch = the current look's own ink). Saved per look:
  `CFQ.inkColors[look key] = { r, g, b }` (missing = the look's own; the old `arcaneInkColor` loads into
  `inkColors.ARCANE`). Ink, title, faded, footer, sub, close, gear, grip, name are shifted by the same step
  as the ink (`P.ShiftColor`), so each look keeps its own shading. Wet ink bleeds in the ink colour anyway; only the
  slate's chalk dust (`bleedFollowsInk`) follows it, bark's carved shadow and leather's lip stay the material's.
  inkRed/inkGreen (counts, turn in) stay. Both rows have "Custom..." (WoW's `ColorPickerFrame`).
  `P.ApplyTallyColors` (run by `P.ApplyStyle`) rewrites `P.STYLES` from the choices; authored colours are
  kept in `P.STYLE_DEFAULTS` (`P.StyleDefaults`).
- **Rigid looks** (`style.rigid`: stone, bark, marble, gilded plate, arcane) can't fold: the page corner is a
  chalked/carved/gilded/engraved/glowing dog-ear mark in the ink colour. `style.inkShadow = { r, g, b, a, x, y }` = text shadow (chalk dust smear; carved = dark shadow
  up-left), `style.bleed` = colour around ticks/strikes. Writing is pale on a dark surface.
  Slate: `style.inkGrain` (`textures/chalk_grain.tga`, slate-coloured speckle tiled 1 texel/px over the chrome)
  makes the chalk rough. Bark forces `font = "SCRAWL"` (straight knife-cut letters; the handwriting button greys out).
- **Wet ink** on looks that drink it (rag, handkerchief, leaf): `style.halo = { alpha, radius }` = 4 copies of the
  words nudged ±radius px under the ink in its own colour (`P.SetHalo`, colour codes stripped); `style.bleedWidth /
  bleedAlpha` widen the bleed round ticks and strikes (`P.BLEED_W/A` in `P.DrawStroke`). A `halo.color` makes it a
  glow instead (arcane, marble; `pulse` = breathes, `pulseSpeed`). Vellum has a faint wet-ink halo.
  Dry looks (pencil, chalk, carved, pressed, engraved) have no halo.
- **"Blotted scrawl"** handwriting (`P.FONT_STYLES`, `drops = true`; Skurri): drops of ink flicked off the quill
  (`P.SetInkDrops`), placed by a hash of the line so they never move between redraws. Mostly **tiny spatters**
  round the stroke (2-5 per line, ~1-2px: the nib scraping the grain); a bigger blot where the quill rested on
  about one line in five (just under the letters' middle); a splash after the last word only rarely (~1 in 12).
  User decision: lots of big blots looked too concentrated on a busy list. Not on looks that force their own lettering.
  The drops are soaked-in blots from `textures/ink_blots` (irregular; dark in the middle, lighter towards a
  ragged bleeding edge — user decision; cells mirrored by the hash), sized so the shape reads — **not** plain circles (user feedback: "computer dots"). The face is drawn
  bolder (`bold` = a second pass 0.8px right, `P.SetBold`) and wet ink hugs it (`haloScale`), so it reads as
  ink soaked in, not blurred. Every copy of a text (bold pass, wet ink) is placed by `P.MatchCopy`: the
  one-line heading (`singleLine`) has copies spanning its box so they cut off with it — a copy that wraps
  drops a word ("Valley") onto the Items heading.
- **Text size** slider (options, `CFQ.tallyTextScale`, 80-150%, saved): lines, notes and footer scale; the heading
  by half as much (`P.TextScale`) so it keeps clear of its underline.
- **Margins follow the window** on texture looks: `style.inset = { l, t, r, b }` fractions (`P.GetPads`,
  `P.LayoutPads` on resize; `pad` is only the minimum). Measure with `[TexGen]::SafeRect(tga)` after regenerating.
- The handkerchief must read as **cloth, not paper**: rounded corners, scalloped lace edge with eyelets
  (`style.cloth`, `P.LayoutClothShape`), woven border stripes, soft gradient creases, drape wrinkles.
  No torn/deckled edges on it.
- Default spot sits `P.PILE_MARGIN_Y` above the chat tabs so the back pages never lap over chat.
- **"For me"** (built, step 1 of the notes plan below): the player's own tasks at the bottom of "Near me"
  (`P.RenderForMe`, called from `P.Render`, both the normal and the empty-page path). `CFQ.notes` = saved
  `QRF_SavedState.notes` (`CFQ.LoadNotes` checks every field; `tasks` in written order, `forMeFolded`).
  Each task: `text`, `done`, `t` (`GetServerTime`), `when` ("10 Nov 21:40", realm calendar via
  `CFQ.NoteTime`), `place` (`CFQ.HerePlace`: mapID, x, y, zone, subzone), `owner` ("Name-Realm"); account-wide,
  every character sees every task (whether to split by character is still **Open**).
  - Rows come from their own pool (`f.forMeRows`, `P.AcquireRow(i, parent, pool)`), inked by `P.InkTaskRow`
    exactly like tally lines (box, tick, strike, halo, ink drops). A row's click finds its task by identity
    (`P.TaskIndex`), never by a position that may have shifted.
  - Click = tick / untick; right-click = re-write in place (empty = rubbed out); shift-click = rub out.
    Its own heading, always shown, **written like the page heading "Near me"** (user decision: title
    writing and ink, gilded first letter on vellum, wet ink, the same double quill underline sized to the
    words; `P.DrawForMeHeading`, height `P.ForMeHeadHeight`). A note after it in the sub ink, as
    "· Dolanaar": "· 3" folded, "· +2" = older tasks that don't fit. Click folds, right-click rubs out the
    ticked ones. Ticked tasks stay struck until rubbed out.
  - **Stands on the page bottom and rises** (user decision: not tucked under the quest lines): writing
    line at the very bottom, tasks above it in written order, heading on top; each new task lifts the
    heading a line. Never rises above where the quest lines end. Not all fit → the **newest** stay (the one
    just written is always in sight).
  - The "+ add a task..." button is **only as wide as its words** (user decision: a full-row button got in
    the way of turning the page at the dog-ear); the writing box also stops `P.CORNER_MAX` short of it.
  - Writing line "+ add a task...": one `EditBox` (`f.forMeEdit`, `P.forMeEditing`), handwriting font, plain
    ink while typing. **The box gets its font before any text** (bug fix: WoW errors on `SetText` without
    one, which left the line showing only "+" and no box; `wowmock.lua` now refuses it too), and
    `P.forMeEditing` is set only after the text is in. Enter keeps, Escape cancels, clicking away keeps (redraw deferred a frame). Hidden
    with the tally → it lets go of the keyboard. `CFQ.CleanNoteText` trims and strips `|` (no colour/link
    escapes yet; item links come with the quick-insert menu). Also `/hanky task <text>` (keeps capitals).
  - Room: no tasks = heading + writing line; with quest lines on the page "For me" keeps at most
    `P.FORME_SHARE` (half) of it (`P.ForMeReserve`); quest lines scroll as before.
  - Open tasks keep the tally up when there are no quest lines anywhere; "...only when something is nearby"
    still puts it away (tasks don't count as nearby). Options: "For me" checkbox (`parchmentOpts.forMe`,
    default on; off = nothing drawn, no room kept, tasks kept). `smoke.lua` keeps it off for the older checks.

## Planned: notes and journal (design agreed with the user, Nov 2026)
Private notes inside the tally. **Step 1 ("For me" tasks + writing line) is built** — see "Design rules";
the rest is not built yet: build to this, and move each part into "Design rules" as it lands. Items marked
**Open** still need the user's call.

**One stack, no separate window** (user decision). Two kinds of writing:
- **"For me" section** at the bottom of the "Near me" page: the player's own **tasks**. Drawn like tally
  rows (hand-inked box, quill tick, strike-through), so reuse the row code. Its heading folds the section
  ("For me (3)") instead of adding a new button (keeps "Keep the tally's controls simple").
- **Journal page**: longer **entries**, newest first, a page in the same pile (not an area page: never
  merged, never counted in `P.MAX_AREAS`). An entry can be opened and written longer (multi-line EditBox
  in a scroll frame, handwriting font). Plain ink while typing; drawn with the look's wet ink / glow /
  chalk once focus leaves.

**The writing line** (last line of "For me": "+ write..."): one input, Enter saves, Escape cancels.
- A small inked switch in front: **box = task** (stays in "For me", never moves on its own), **quill =
  entry** (stamped, then leaves "For me" and goes to the Journal). The entry visibly flies off into the
  Journal knot and the knot nudges, so it never looks deleted.
- A **"with" glyph** (two figures): opt-in per entry (remembers the last choice) — stamps the party/raid
  names ("with Sam, Rosie"; cap ~5, then "and N others"). Faded and inert when solo. Optional: target name.
- **Right-click while typing = quick-insert menu**, our own menu in the look's ink/material (not Blizzard's
  drop-down; same strata care as the Look list). Categories open a side list on hover:
  - **Players**: recently played with (party/raid roster seen on `GROUP_ROSTER_UPDATE`, last 10-15, newest
    first, saved), current target first if a player. The "with" glyph uses the same list.
  - **Enemies**: recently killed, current target, the quests' slay targets (`qData.taskObjectives`).
  - **Items**: recently looted + quest items, inserted as item links (tooltip on hover in the journal).
    **Open:** links drawn in the ink colour with a faint underline (suggested), quality colour only in the
    tooltip.
  - **Quests**: tracked quests (quest links). **Places**: here (subzone, zone) and the quests' areas.
  - Later maybe: NPCs talked to. Optional shortcut: typing `@` opens Players.
- Right-click elsewhere is unchanged: on a finished task/entry = its own menu (edit, move to journal,
  delete, remove a name); on a quest line = quest log.

**Every task and entry is tied to a place**: subzone, zone, mapID and x/y where it was written.
- Entry stamp: realm date/time + place, e.g. "10 Nov, 21:40 · Goldshire" (+ "with ..."). Time from
  `C_DateAndTime.GetCurrentCalendarTime` (realm clock, same as the in-game calendar), also stored as
  `GetServerTime()` for sorting; `pcall`, fall back to `time()`/`date()` (PC clock) — check in game which
  this client gives. There is no separate Azeroth date. **Open:** optional Shire Reckoning month names.
- Hovering an entry shows `CFQ.ShowMapPreview` with a dot where it was written. Clicking an entry's
  place stamp filters the Journal to that place (click again = all). No filter buttons.
- Tasks: **Open** — "everywhere" (suggested default) or "here" (shows in "For me" only near where it was
  written); right-click switches (built: everywhere only). Built: tasks don't count as nearby for
  `hideWhenNothingNearby` (**Open** to revisit).
- Ticked tasks: built as "stay struck until rubbed out" (**Open** to revisit). Optional: ticking logs
  "Done: ..." to the Journal (off by default). Right-click a task → "Move to journal" (needs the step-4 menu;
  right-click currently re-writes).

**Knots = the two quick tabs** (user decision; replaces the idea of side tabs — **no ribbons**, minimal):
- **Top-right knot = "Near me"** (the front page): hangs off the sheet's right edge just outside the
  corner, clear of the close button (`closeBtn`, TOPRIGHT of the chrome).
- **Bottom-right knot = Journal**: hangs from the bottom edge **just left of the dog-ear, never
  overlapping it**. The resize grip stays bottom-left; the dog-ear still turns area pages.
- **On hover a knot dangles** like it was tapped (swings round its tie point, a few damped swings), the
  way the dog-ear lifts on hover. Tooltip names the page. Clicking the knot of the page you're on flips
  back to where you were.
- Cloth/paper looks: a real knot of the material (a procedural knot shape from `tools/TexGen.cs`,
  textured with the look's own image like `P.DrawMaterialFold`). Rigid looks: a knot **mark** in their
  lettering (chalked / carved / gilded / engraved / a glowing arcane loop) that glints instead of
  swinging. See-through window: an inked knot glyph.

**Saved data** (`QRF_SavedState`, account-wide; `parchmentOpts` only loads booleans, so a new key):
`notes = { tasks = {...}, journal = {...}, recentPlayers = {...}, recentKills = {...}, recentLoot = {...} }`.
Each task/entry: `text`, `kind`, `done`, `t` (server time), `stamp`, `place = { mapID, x, y, zone,
subzone }`, `with = { names }`, `owner = "Name-Realm"` (so an entry can be one character's or all of
them: **Open**). Stays only on the player's PC (WTF folder); never sent anywhere. Written on reload /
logout / quit only: a client crash loses that session's new writing.

**Auto-recording** (user decision): the addon writes a Journal entry itself when something passes a
threshold set in the **options panel** (never on the tally). Each trigger is its own on/off:
- **Rare loot**: WoW gives **no drop rates** (and there's no bundled drop database), so it means:
  - **item quality** at or above a chosen level (e.g. Rare and up);
  - **first time ever looted** (remember every item ID looted; catches odd greys/whites);
  - later extra: **our own observed rate** ("seen in under N% of kills"), counted from loot tries like the
    quest-item counts behind `P.RULE_OUT_LOOTS`; only meaningful after many kills.
- **Achievements earned** (`ACHIEVEMENT_EARNED`): only offered if this client has achievements — check in
  game first; hide the option when the API/event is missing.
- **Level ups** (`PLAYER_LEVEL_UP`): every level, or every 5 / 10.
- **Rare / elite kills** (`UnitClassification`: rare, elite, rareelite, worldboss).
- **New places**: first time entering a zone / subzone.
- **Quests turned in**: all, or only those that took longer than X days.
- **Deaths** (optional): "Died to Hogger, Elwynn Forest".
- **No money trigger** (user decision).

Keep it from turning into spam: auto entries are drawn differently (faded ink or a small stamp) so the
player's own writing stands out; similar events within a few minutes merge into one entry ("Looted 3 rare
items in the Fargodeep Mine"); everything is **off by default except level ups and first-time rares**.

**Build order**: ~~"For me" tasks + writing line~~ (done) → Journal page + entries/stamps (+ the task/entry
switch on the writing line) → knots → "with" + quick-insert menu → auto-recording.

## Code conventions
- Main chunk is near Lua's 200-local limit: put new state/functions in the `CFQ` or `P` (parchment)
  tables, not new top-level locals.
- Saved settings: `QRF_SavedState` (account-wide). Keep old keys loadable; new keys need defaults.
  `parchmentOpts` only loads boolean values. The saved look loads if its key is in `P.STYLES` (`LoadState`
  reaches it as `CFQ.P`: `P` is declared later), so a new look needs no change there (marble / gilded /
  vellum used to be dropped on every reload).
- Wrap risky Blizzard API calls in `pcall`; layout passes are guarded so an error can't freeze the tracker.

## Naming
- The folder name, `.toc` filename, `ADDON_LOADED` check and `.pkgmeta` `package-as` must all match.
  The SavedVariables file in `WTF\Account\<id>\SavedVariables\` is named after the folder too.
- **Players see "HandkerSheaf"** (user decision, after v2.4.1): `.toc` `## Title`, `CONFIG.DISPLAY_NAME` (options
  panel, Settings list entry) and every chat/tooltip prefix. `CONFIG.ADDON_NAME` stays "Handkerquest" (internal
  id); never use it for visible text.
- Folder must be `Interface\AddOns\Handkerquest` (matches `Handkerquest.toc` and `arg1 == "Handkerquest"`).
  Settings file: `WTF\Account\<id>\SavedVariables\Handkerquest.lua` (was `CacheForQuest.lua`).
- The code file's name is free: only the `.toc` file list points at it (`HandkerSheaf.lua`). Renaming it
  doesn't touch the folder, addon name or settings. Never rename the folder/`.toc`/`package-as` — that
  shows up as a new addon to players and their settings file would be left behind.
  `smoke.lua` checks every file the `.toc` lists exists.
