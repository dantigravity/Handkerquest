# Handkerquest — notes for Claude

WoW addon: Objective Tracker sorting/filters + (?)/(•••) quest stacks, and the "Field Tally" parchment
(a pile of handwritten pages listing quest items to gather and tasks to do). Single file: `Handkerquest.lua`.
Version lives in `Handkerquest.toc` (`## Version`) and `CONFIG.VERSION`; release commits are titled `vX.Y.Z`.
Formerly "Cache ForQuest" (renamed in v1.3.0: handkerchief + quest, after Bilbo setting off without his handkerchief).
Internal names keep the old `CFQ` / `QRF_` prefixes on purpose — renaming `QRF_SavedState` would wipe
players' settings. Slash: `/hanky`, `/handkerquest`, legacy `/cfq`.

## Client
- Flavor "wowf" (WoW Forever), `## Interface: 16001`, but a **retail-style UI**: `QuestObjectiveTracker`
  module with `.ContentsFrame`, `C_QuestLog`, `C_SuperTrack`, `Settings` canvas panels.
- Client fonts are `.slug` files — don't ship custom TTFs without testing. The tally uses built-in
  `Fonts\MORPHEUS.TTF` (Quill script), `SKURRI.TTF` (Rough scrawl, Blotted scrawl) or the standard font
  (Plain print), user-selectable in `P.FONT_STYLES`.
- Most of the UI is drawn in code (`SetColorTexture`, gradients, `CreateLine`, Blizzard textures). The only
  art files are the texture looks in `textures/`, all procedural (no stock or Blizzard art), generated by
  `tools/TexGen.cs`. 32-bit uncompressed TGA, alpha = the shape, 512×512 unless noted. Regenerate from PowerShell:
  `Add-Type -Path tools\TexGen.cs -ReferencedAssemblies System.Drawing`, then
  - `[TexGen]::Rag(...)` → torn_rag, `::Crumpled(...)` → crumpled_paper
  - `::Stone(tga, png, 512, 5)` → stone, `::Bark(tga, png, 512, 3)` → bark, `::Leaf(tga, png, 512, 9)` → pipeweed_leaf
  - `::Leather(tga, png, 512, 4)` → etched_leather
  - `::ArcaneHaze(tga, png, 256, 2)` → arcane_haze (256), `::ArcaneRing(tga, png, 512, 7)` → arcane_ring
    (white lines; tinted and added in game)
  - `::ChalkGrain(tga, png, 128, 21, 0.165, 0.175, 0.195)` → chalk_grain (128, tiles)
  - `::InkBlots(tga, png, 256, 11)` → ink_blots (256, 2x2 atlas of white blots; tinted with the ink in game)

  Re-measure `inset` / `imageCorner` with `[TexGen]::SafeRect(tga)` after regenerating.
  `media/` (CurseForge GIFs) and `tools/` are excluded from the package in `.pkgmeta`.

## Testing
- `"C:\Program Files (x86)\Lua\5.1\lua.exe" smoke.lua Handkerquest.lua` (Lua 5.1 = WoW's version).
  Must end with `N passed, 0 failed`. Syntax only: `luac.exe -p Handkerquest.lua`.
- `wowmock.lua` is loose (unknown capitalized methods are no-ops): catches logic errors and crashes,
  not visuals. Add `check(...)` lines to `smoke.lua` for every feature/fix; stub missing APIs in the mock.
- The user tests in game; say plainly what was and wasn't verified there.

## Design rules (each was a bug fix or a user decision — don't undo)
- **Stacking is visual only.** A deck holds only quests that already have a native tracker block;
  toggling stacks never adds/removes quest watches. Toggles call `CFQ.RequestNativeTrackerUpdate()`
  so Blizzard re-shows its blocks. `/hanky debug` dumps the tracker for in-game diagnosis.
- **Field Tally lines** (user decision, v2.2):
  - **Items** = item objectives (`obj.type == "item"`; wording fallback when untyped) → `qData.itemObjectives`.
  - **Tasks** = enemies to slay and other steps, **only when there's more than one thing to do**: a count above 1,
    or a quest with several objectives (`CFQ.ExtractTaskObjectives` → `qData.taskObjectives`; `kind` = `slay` /
    `task`, both shown as "Tasks"). A task of one (`single = true`) is just a box: no "0/1".
  - Droppers, loot scans, hunt spots and minimap pins stay items-only. A slay line burns while your target is
    one of them (`CFQ.TargetIsToSlay`).
- **Keep the tally's controls simple** (user decision, v2.2): three inked 16px toggles left of the gear, nothing
  else. Items (a basket) and tasks (a sword) = `parchmentOpts.tallyLoot` / `tallyTasks` (one always stays on,
  `P.SetTallyShows`); tasks apart (lines) = `tallySeparate` (items first, then tasks under "Items" / "Tasks"
  headings, `P.DrawKindHeading`). Full ink = on, faded = off (`P.DrawQuickButton`, glyphs in `P.QUICK_GLYPHS`).
  **No other line orders** (A-Z, closest to done, presets and a mix menu were tried and removed): lines keep
  the tracker's quest order. Switching items or tasks off never puts the tally away
  (`P.ShouldHideUnfiltered`), even with "hide when nothing is nearby". Same three choices in the options panel.
- Rows: hand-inked box, quill tick, strike-through only over "count  name" (one strike per wrapped
  line); "(turn in)" is a separate unstruck note.
- **Page 1 is always "Near me"** (items within the Near me distance of the player, or progressed in the
  last 3 min). Pages 2+ are area pages grouped by `CFQ.pageGrouping`: `AREA` (explored subzone via
  `C_MapExplorationInfo`), `ZONE`, or `RADIUS` (leader clustering, optionally linked to the ••• slider).
  Pages with the same name always merge — never "Name II". In the options `RADIUS` is called **"Clusters"**
  and its slider "Cluster size" (user decision: "Distance" read as a distance, not a place).
  Quest positions: waypoint, then `CFQ.QuestPosNearPlayer` (`C_QuestLog.GetQuestsOnMap` on your map and its
  parents, so a new character needn't open the world map), then the world-map pin cache. A position on another
  map (Elwynn vs Northshire) is translated onto yours (`P.TranslatePos`). With none, a tracked quest whose log
  heading names your zone **or sub-zone** counts as near.
- "...only when something is nearby" (`hideWhenNothingNearby`) sits indented right under "Show the parchment
  tally list" (user decision). Switching the tally on while it stays hidden prints why (`P.TurnTallyOn`,
  `P.HiddenReason`). The options panel is a scroll frame (it's taller than the Settings window).
- Dog-eared bottom-right corner turns pages; resize grip is bottom-left. No ribbons, no Area/Zone/All cycle.
  On texture looks the fold is the material itself (`P.DrawMaterialFold`): the fold square reaches the
  **image's** corner, so the flap is the material's real edge (curved, lobed, torn) mirrored across the fold
  (8-value `SetTexCoord`) and the uncovered part follows that edge too; the crease is a dark strip of the
  material itself. No straight drawn edges/lines there (they'd overhang a curved edge). Rows are made lazily.
  `style.foldAtEdge` (leaf) keeps the square on the material's corner: its long edge runs along the fold.
  `P.PlaceCorner` puts it on the image's real corner (`style.imageCorner`, fractions measured from the TGA),
  re-placed on resize.
- No brass tack / yellow square at the top of the pile (removed at the user's request in v1.4).
- **Clicking a tally item = clicking the quest's icon in the Objective Tracker** (user decision, v1.4):
  `CFQ.ToggleSuperTrack` super-tracks the quest (click again to stop), adds no watches, opens nothing.
  Blizzard then shades the quest area on the map itself. Right-click = quest log. The addon draws
  **nothing on the world map** (an earlier ring/blob overlay covered Blizzard's highlights and was removed).
  The pin filter never dims or badges quest-area highlight pins (pins with `DrawBlob`).
- Hunting grounds = spots where the item ticked up (`CFQ.huntSpots`, saved) + the quest's map POI.
  Glow = in hunting grounds; fire = target drops it ("sure"), smoulder = name-only guess.
- **Droppers are evidence-first** (`CFQ.FindTargetDrops`): sure = the loot window showed the item from that
  npc (`CFQ.ScanLootWindow`, `GetLootSourceInfo` per slot) or the unit tooltip names the item/quest.
  Name guess only if not ruled out: ≥`P.RULE_OUT_LOOTS` tries without it, `UnitIsRelatedToActiveQuest`
  false, or tooltips list quests on this client but not this one. No bundled drop database.
- Hovering a tally item: tooltip goes beside the tally on the roomier side (`P.PlaceTooltip`); a small
  map preview (`CFQ.ShowMapPreview`: zone tiles, quest-area blob, rings, player dot) takes the candidate
  spot that is on screen and overlaps least (tally/tooltip weighted heavily, then `P.AVOID_FRAMES`).
  Blizzard's blob is only ever drawn *inside the preview*.
- Minimap: amber pins for the super-tracked quest's looted spots (`CFQ.UpdateMinimapPins`), on the rim
  when out of range; world coords: X = north, Y = west.
- Parchment look has no shaded header band (removed: it grew with the window). Grain is cropped from
  plain parchment below the quest-frame header art.
- Looks (`CFQ.parchmentStyle`, `P.STYLES`, in Look-button order). All tally colours come from the style
  table: don't hard-code ink colours.
  - `HANDKERCHIEF`, `PARCHMENT` (drawn in code).
  - `CRUMPLED`: crumpled-and-flattened paper, pencil.
  - `RAG` (**default**, user decision): a strip torn off a dwarf's shirt: cream cotton weave, irregular torn
    edges with loose threads, the shirt's folded hem along the bottom with **no stitch/dotted line** (removed
    at the user's request), soot ink.
  - `STONE`: smooth dark river slate, chalk.
  - `BARK`: jagged chocolate-brown bark slab, letters carved into the reddish underbark.
  - `LEAF`: cured pipe-weed leaf (a nod to Longbottom Leaf): gold-brown, veins, **near-black** ink (brown ink
    vanished into the curing spots, user feedback); bends, so it keeps
    the textured fold. Its back pages **fan out from the stem** (`style.fan`) instead of lying flipped.
  - `LEATHER` ("Etched leather"): a rough-cut piece of supple tan garment leather, hide-shaped (leg lobes,
    knife-cut edges, a nick or two), soft drape folds, fine grain; no tooling or stitching (user decision).
    Letters pressed in (dark ink, pale lip below-right via `inkShadow`); real fold.
  - `ARCANE`: a mage's writing hanging in the air: violet haze, a rune circle (`style.arcane`, added light,
    turning slowly on the top sheet), rising motes, a pulsing violet glow round the words, glowing corner
    mark, no pile (`P.LayoutArcane` / `P.AnimateArcane`). The circle is our own triangle-and-random-runes
    design, not WoW art, and deliberately has no six-pointed star.
  - `NATIVE`: see-through window, plain UI font, no pile.

  Texture looks set `style.image`: the sheet is one textured quad, the shadow is the same image tinted black
  and the pile is the image flipped per page (except the leaf's fan).
- **Rigid looks** (`style.rigid`: stone, bark, arcane) can't fold: the page corner is a chalked/carved/glowing
  dog-ear mark in the ink colour. `style.inkShadow = { r, g, b, a, x, y }` = text shadow (chalk dust smear; carved = dark shadow
  up-left), `style.bleed` = colour around ticks/strikes. Writing is pale on a dark surface.
  Slate: `style.inkGrain` (`textures/chalk_grain.tga`, slate-coloured speckle tiled 1 texel/px over the chrome)
  makes the chalk rough. Bark forces `font = "SCRAWL"` (straight knife-cut letters; the handwriting button greys out).
- **Wet ink** on looks that drink it (rag, handkerchief, leaf): `style.halo = { alpha, radius }` = 4 copies of the
  words nudged ±radius px under the ink in its own colour (`P.SetHalo`, colour codes stripped); `style.bleedWidth /
  bleedAlpha` widen the bleed round ticks and strikes (`P.BLEED_W/A` in `P.DrawStroke`). A `halo.color` makes it a
  glow instead (arcane; `pulse` = breathes). Dry looks (pencil, chalk, carved, pressed) have no halo.
- **"Blotted scrawl"** handwriting (`P.FONT_STYLES`, `drops = true`; Skurri): drops of ink flicked off the quill
  (`P.SetInkDrops`), placed by a hash of the line so they never move between redraws. Mostly **tiny spatters**
  round the stroke (2-5 per line, ~1-2px: the nib scraping the grain); a bigger blot where the quill rested on
  about one line in five (just under the letters' middle); a splash after the last word only rarely (~1 in 12).
  User decision: lots of big blots looked too concentrated on a busy list. Not on looks that force their own lettering.
  The drops are soaked-in blots from `textures/ink_blots` (irregular; dark in the middle, lighter towards a
  ragged bleeding edge — user decision; cells mirrored by the hash), sized so the shape reads — **not** plain circles (user feedback: "computer dots"). The face is drawn
  bolder (`bold` = a second pass 0.8px right, `P.SetBold`) and wet ink hugs it (`haloScale`), so it reads as
  ink soaked in, not blurred. Every copy of a text (bold pass, wet ink) is placed by `P.MatchCopy`: the
  one-line heading (`singleLine`) has copies spanning its box so they cut off with it — a copy that wraps
  drops a word ("Valley") onto the Items heading.
- **Text size** slider (options, `CFQ.tallyTextScale`, 80-150%, saved): lines, notes and footer scale; the heading
  by half as much (`P.TextScale`) so it keeps clear of its underline.
- **Margins follow the window** on texture looks: `style.inset = { l, t, r, b }` fractions (`P.GetPads`,
  `P.LayoutPads` on resize; `pad` is only the minimum). Measure with `[TexGen]::SafeRect(tga)` after regenerating.
- The handkerchief must read as **cloth, not paper**: rounded corners, scalloped lace edge with eyelets
  (`style.cloth`, `P.LayoutClothShape`), woven border stripes, soft gradient creases, drape wrinkles.
  No torn/deckled edges on it.
- Default spot sits `P.PILE_MARGIN_Y` above the chat tabs so the back pages never lap over chat.

## Code conventions
- Main chunk is near Lua's 200-local limit: put new state/functions in the `CFQ` or `P` (parchment)
  tables, not new top-level locals.
- Saved settings: `QRF_SavedState` (account-wide). Keep old keys loadable; new keys need defaults.
  `parchmentOpts` only loads boolean values.
- Wrap risky Blizzard API calls in `pcall`; layout passes are guarded so an error can't freeze the tracker.

## Naming
- The folder name, `.toc` filename, `ADDON_LOADED` check and `.pkgmeta` `package-as` must all match.
  The SavedVariables file in `WTF\Account\<id>\SavedVariables\` is named after the folder too.
- Folder must be `Interface\AddOns\Handkerquest` (matches `Handkerquest.toc` and `arg1 == "Handkerquest"`).
  Settings file: `WTF\Account\<id>\SavedVariables\Handkerquest.lua` (was `CacheForQuest.lua`).
